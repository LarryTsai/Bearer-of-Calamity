# 《劫》World Graph：橫向世界運行 Agent 系統

> 給 Claude Code
> 的開工規格。目標不是「多塞支線」，而是把目前幾條角色縱線，擴張成一個在主角不存在時仍會自行運轉的世界。

## 1. 核心問題

目前《劫》已有很強的縱向故事線：劫、瘋、生、青璃、文奕、荒、魔女、四伴星等角色，各自在線上經歷小、中、大型事件。

但整體仍比較像：

``` text
時間 →
劫    ───●────●────◎────●────◎────→
生       ───●────────●──────●─────→
瘋          ──●────●─────◎────────→
荒                    ───●────◎────→
```

問題不是核心角色不夠，而是「線與線之間大量空白」。

目前很多世界事件仍以「陸沉到了，所以事件開始」的方式存在；角色離開主視角後，也容易暫停運算。

真正要補的是：

> **世界在沒有陸沉的地方，也必須持續發生事情。**

## 2. 目標：World Graph

未來世界應由大量節點與關係組成，而不是只有主角時間線。

節點至少包括：

-   人物、宗門、家族、古國、種族、城市、地域
-   商會、散修組織、禁制／丹道／煉器流派
-   資源、遺跡、傳承、戰爭、歷史事件
-   利益、恩怨、聯姻、師承、交易、情報、文化、世界危機

Edge 可以是：

-   合作／敵對
-   利益衝突
-   從屬
-   交易
-   血緣／師承
-   情感
-   歷史仇恨
-   資源依賴
-   情報交換
-   地緣衝突
-   暫時聯盟

核心原則：

> **縱向是角色命運，橫向是同一時刻的世界；交叉形成事件，多個交叉互相影響才形成
> World Graph。**

## 3. 橫向時間切片

對現有 Timeline 的每個重要 checkpoint，增加一次「世界橫向掃描」。

例如：

``` text
                  滅族   百斷山   太玄宗   七峰比試   禁制古域
────────────────────────────────────────────
陸沉              ●─────●───────●────────●────────●
宗門世界           ○─────○───────●────────◎────────○
古國政治           ●─────○───────○────────○────────●
禁制文明           ○─────●───────○────────○────────◎
丹道文明           ○─────○───────●────────○────────○
妖族／異族         ●─────◎───────○────────●────────○
散修／民間         ○─────●───────○────────○────────●
世界危機           ○─────○───────○────────○────────●
```

不是每格都要成為正式劇情。

例如一條世界線可以只是：

T1：北域兩國交戰。\
T2：戰爭惡化，出現流民。\
T3：流民修士形成互助組織。\
T4：逐漸武裝化成散修勢力。\
T5：開始與宗門產生利益衝突。\
T6：陸沉才第一次遇見其中的人。

這代表這個勢力不是為了陸沉某一章才出生。

## 4. World Layer Agent

第一版不要建立二十幾個 Agent。建議 **6～7 個長期 World Agent + 1 個
World Integrator**。

### A. 宗門／修行勢力 Agent

負責各宗門、各峰、長老派系、弟子世代、資源競爭、外交、內部政治、天驕興衰。

核心問題：

> 如果陸沉不存在，這些宗門現在正在做什麼？

### B. 古國／政治／地緣 Agent

負責古國、王朝、城邦、皇族、邊境、戰爭、聯盟、政治婚姻、領土、資源與外交。

政治事件必須能自行演進，不能全部變成主角任務。

### C. 修行文明 Agent

負責禁制、丹道、陣法、煉器、特殊傳承、學派、世家、流派衝突、正統／異統。

例如禁制世界應自行存在正統世家、散修禁師、偏門流派、老禁師、年輕天驕、失敗天才、交易市場、傳承爭奪與理念衝突。

### D. 異族／妖族／地域文明 Agent

負責妖族、靈族、古族、特殊血脈、部落、祖地、遷徙、族群恩怨，以及不同文明的利益與價值觀。

異族不能只是提供敵人。

### E. 散修／民間／經濟 Agent

負責散修、商會、黑市、城市居民、傭兵、探險者、小型組織、商路、資源價格、人口移動與底層修士生活。

避免世界只剩「頂級天驕＋大宗門」。

### F. 世界線人物 Agent

建立並維護「不是主角團，但自己也像另一部小說主角」的人。

這些人可以跟陸沉合作、競爭、敵對、互相欣賞，然後真正分開。

重要原則：

> **不是每個好角色都必須加入陸沉。**

他可以說「我要回我的宗門」、「那座城是我的家」、「你的道不是我的道」，然後真的離開。數百章後才可能再見。

### G. 世界危機／歷史演化 Agent

負責古老封印、遺跡甦醒、天地異變、戰爭、災害、上古因果、規則變化、跨區域事件與長期伏筆。

同樣不能全部因陸沉而發生。

## 5. World Integrator：核心 Agent

各 World Agent 發散後，必須交給 **World Integrator / 世界編織者**。

Integrator 不是繼續增加設定，而是找：

> **哪些看似不同的事情，其實應該是同一件事？**

例如：

-   禁制 Agent：某世家尋找失傳禁圖。
-   政治 Agent：某皇族秘密挖掘古遺跡。
-   異族 Agent：某族認為祖地即將重開。
-   民間 Agent：散修大量前往某區採集異常靈材。

Integrator 可以將四件事合成同一座古遺跡。

如此才形成網，而不是 20 條互不相關的支線。

Integrator 還必須檢查：

-   是否設定過度膨脹？
-   是否有重複功能的人物／勢力？
-   是否能合併節點？
-   是否與既有 GitHub canon 衝突？
-   是否又變成所有事件都圍繞陸沉？
-   哪些事件只應存在背景？
-   哪些值得與主線交叉？
-   哪些應留待幾十／幾百章後回收？

## 6. World Layer 與 Story Layer 分離

``` text
WORLD LAYER

宗門 Agent
政治 Agent
文明 Agent
異族 Agent
民間 Agent
世界線人物 Agent
世界危機 Agent
        ↓
WORLD INTEGRATOR
        ↓
WORLD STATE / WORLD GRAPH
        ↓
STORY DIRECTOR
        ↓
Actor Agents / Scene Design / Chapter Editor
Continuity / Character Review / 既有審查 Agent
```

World Layer 問：

> **這個世界現在正在發生什麼？**

Story Layer 才問：

> **其中哪些事情值得真正寫進小說？**

## 7. 陸沉不是事件發生器，而是事件碰撞者

例如「雷礦」。

不要寫成：

``` text
陸沉需要雷礦 → 前往 → 遇敵 → 得機緣
```

而應先讓世界存在：

``` text
古國 A 擁有雷礦
        │
太玄宗維護防禦陣
        │
禁制世家想取得陣圖
        │
妖族認為此處原為祖地
        │
散修長期偷採雷晶
        │
雷礦近期發生異變
        │
某少年正在尋找失蹤父親
```

然後：

> **陸沉來了。**

他碰任何一個節點，都可能震動其他節點。

而他離開後，雷礦、古國、妖族問題、禁制世家的企圖與那名少年仍繼續存在。

## 8. Agent 必須有持續狀態

禁止每個 checkpoint 重新 brainstorming。

例如：

T1：太玄宗與玄劍門因靈礦摩擦。\
T2：高層談判。\
T3：高層和解，但年輕弟子仇恨仍在。\
T4：兩宗弟子外出歷練時爆發衝突。\
T5：陸沉才第一次碰到這條線。

每次輸出必須讀取前一 checkpoint 的 state 並演化。

## 9. World Agent 標準輸出

建議結構：

``` yaml
time_point:
domain:

current_state:
changes_since_last_checkpoint:

active_factions:
active_characters:
new_characters:

ongoing_conflicts:
new_conflicts:
resolved_conflicts:

resources_in_motion:
relationships_changed:
hidden_events:

possible_future_pressure:
intersection_with_other_domains:

intersection_with_lu_chen:
  none | indirect | direct

should_enter_main_story:
  no | background | mention | subplot | major
```

非常重要：

``` yaml
intersection_with_lu_chen: none
```

必須是正常且大量存在的答案。

## 10. Integrator 標準輸出

``` yaml
time_point:

merged_world_events:
new_graph_nodes:
new_graph_edges:

cross_domain_conflicts:
cross_domain_alliances:

events_that_can_be_merged:
events_that_should_remain_independent:

background_only_events:
potential_story_intersections:
future_payoffs:

continuity_risks:
world_density_check:
protagonist_centrality_check:
```

`protagonist_centrality_check` 必須特別檢查：

> 是否又變成所有事情都因陸沉而發生？

若是，退回修改。

## 11. 人物分級

不要再讓每個有名字的人都需要一份完整 CHARACTER.md。

### Level A：核心人物

劫、生、瘋、青璃、文奕、荒、魔女、四伴星等真正核心角色。

需要完整 Profile。

### Level B：篇章人物

每個中大型篇章可以自然出現約 3～8 個有辨識度的人，其中可能只有 1～2
個長期延續。

只需要身分、動機、關係、性格與本篇目的。

### Level C：世界人物

城主、商人、老禁師、普通宗門弟子、散修、帶路者、族老、黑市人物、失敗天才等。

只需要足以讓世界成立。

不必成為仙王、不必加入主角團，也不必強制回收。

## 12. 第一個實驗區：下界

不要立刻重構整部小說。

第一階段只做：

# **下界 World Graph**

盤點至少包括：

-   太玄宗及各峰
-   其他宗門
-   古國／城市
-   禁制圈
-   丹道圈
-   散修圈
-   妖族／異族
-   百斷山相關勢力
-   商會與資源流通
-   古遺跡
-   歷史恩怨
-   世界線人物

下界目前可能同時有「篇幅偏短」與「橫向密度不足」兩個問題，因此最適合測試。

## 13. 不要先加章數

第一步禁止直接決定「下界增加 30／50 章」。

正確流程：

1.  讀取 GitHub 現有 canon、timeline、characters、outlines。
2.  建立下界 checkpoint。
3.  對每個 checkpoint 執行 World Agents。
4.  Integrator 合併成 World Graph。
5.  找出自然與既有主線交叉的節點。
6.  評估哪些只留背景、哪些一句帶過、哪些成為小事件、哪些值得升為中篇。
7.  最後才由 chapter/outlining Agent 決定是否增加篇幅。

原則：

> **不是為了讓下界變長而加故事；是先讓下界活起來，故事自然會變多。**

## 14. 世界必須存在「與劫完全無關的事情」

這是驗收重點。

每個 checkpoint 都應存在若干：

-   劫不知道的事件
-   劫沒有參與的戰鬥
-   劫沒有見過的人
-   不因劫而形成的關係
-   不因劫而開始的戰爭
-   不會在近期與主線交叉的世界變化

否則 World Graph 仍只是偽裝過的主角支線表。

## 15. Claude Code 第一階段任務

先不要直接改小說正文或大綱。

請先：

1.  完整讀取目前 repository 中與下界相關的
    canon、timeline、outline、character、faction、location、pending
    decisions。
2.  列出現有下界時間 checkpoints。
3.  畫出目前已有的「縱線＋節點」。
4.  找出橫向世界空白。
5.  提出 World Agent 架構，優先復用現有 agent，不要無限制增加 agent。
6.  若需新增 agent，說明每個 agent 與現有 agent 的責任邊界。
7.  設計 World State 與 World Graph 的持久化檔案格式。
8.  用下界做一次 dry run。
9.  先產出分析與候選 World Graph，**不要直接改 canon**。
10. 讓作者 review 後，再決定哪些內容正式寫入設定。

## 16. 第一階段驗收標準

成功不是「新增了多少角色」。

成功應該表現在：

-   拿掉陸沉後，下界仍然有事情發生。
-   每個主要勢力都有自己的目標與壓力。
-   不同領域的事件會互相影響。
-   人物會在陸沉不在場時成長、失敗、結盟、反目。
-   新角色大部分不會加入主角團。
-   大量世界事件只作為背景存在。
-   舊事件因為橫向關係而獲得新的因果深度。
-   百斷山等篇章不再像獨立副本，而像多條世界線在同一地點碰撞。
-   世界不因陸沉離場而停止。
-   沒有破壞現有重要 canon。
-   不為了「世界很大」而製造大量無功能設定。

## 17. 最終設計哲學

我們不是要把《劫》從：

> 10 個角色變成 100 個角色。

也不是從：

> 300 章硬灌成 500 章。

真正要做的是把：

> **「這是陸沉的故事，旁邊掛著一個世界。」**

變成：

> **「這是一個龐大且自行運轉的世界，而我們選擇跟著陸沉走過其中一條路。」**

最後牢記：

> **縱向是角色命運。**\
> **橫向是同一時刻的世界。**\
> **交叉是事件。**\
> **事件彼此留下後果。**\
> **後果繼續演化。**\
> **最後才形成真正的 World Graph。**
