本文件依 [00_REBUILD_CHARTER.md](00_REBUILD_CHARTER.md) 的新入口規則執行；各篇處理方向以 [01_ARC_REASSESSMENT.md](01_ARC_REASSESSMENT.md) 為逐篇對照。這是作者改變全書工作方向後的安排，不是舊正文的修補清單。

## 一、這次真正要做的事

作者已明確要求：自創故事先搬離現行寫作入口，重新架構全書，補大綱與每篇大概內容，確認方向後再補肉。舊版可能不行，不能因為已寫完，就把它當成新版必須保住的答案。

順序固定為：**確認封存範圍並保留可追溯原檔 → 回收作者原始 idea 與最想看的經歷 → 重建全書架構 → 補全書大綱 → 為各篇寫完整起承轉合的梗概 → 作者一起看完整體方向 → 再安排正文。**

最新校正見 [找回原始奇想](04_ORIGINAL_IDEA_RECOVERY.md)：先把 Agent 後加的任務與流程暫時拿開，從作者最初讓人想看的世界與人物出發。設定審查負責讓奇想站得住，不能把不好落地的奇想全部改成勤務。本輪已保存作者重述的八個核心 idea；歷史原始來源尚待追溯，不宣稱已完成全書回收。

「KEEP／保留」只表示保留該篇值得留下的核心主題、人物價值或必要大事件；不保證沿用舊文、既有橋段、章數、比例與故事順序。某篇主題值得保留，仍可能需要整篇重寫。舊文可供參考，不具有阻止重新設計的優先權。

全書架構確定以前，不因某一篇容易寫、已有很多正文，或某位 agent 有靈感，就先把該篇擴成新版正文。古界或帝關可以先設計病灶與方向，但全書梗概要一起看過，才排正文寫作。

## 三、封存要分清楚什麼

封存的目的，是讓新版架構有清楚的工作入口，同時完整保留舊稿、作者原始想法及可追溯關係。不能把「搬離現行入口」做成刪除故事資產，也不能把人物設定與純原作資料混搬抹除。

| 層次 | 包含內容 | 本輪安排 |
| --- | --- | --- |
| 舊故事正文 | 各章群來源章、相關尾聲／插段及其既有目錄 | 列入全書封存提案，逐章群列精確路徑；尚不搬動 |
| 舊故事方案 | `outlines`、`drafts` 中的原創大綱、章卡、故事提案 | 列出所屬篇章與版本；作者原始發想完整保留，不能只留濃縮結論 |
| 閱讀與發布副本 | `novel` 內閱讀鏡像、`published` 及相關產物 | 與來源章配對處理，標記舊版身分；避免新入口仍指向已封存版本 |
| 配套索引 | 全書目錄、篇目錄、總綱中的舊正文入口、舊稿進度 | 先區分哪些跟隨舊稿封存、哪些保留為新入口；不能留下失效連結 |
| 混合性事件檔 | `events` 中的原創事件、修行所得、傷勢與關係依賴 | 拆分判讀：舊橋段可封存，已確認核心設定與作者決策須有去處，不整批搬空 |
| 人物與能力設定 | 角色、關係、雷種、命圖、兵器、境界時間線等 | 保持可讀；標示作者確認核心、原作約束、舊故事衍生、待重審四類。核心保留不等於舊橋段保留 |
| 純原作資料 | 《完美世界》的原作摘錄、定位、時空與人物參考 | 不作為舊原創故事封存；保留資料身分與來源，不把未核提案升格為原作事實 |
| 作者指令與討論紀錄 | 已明確提出的創作方向、人物定位、待決定事項 | 完整保存；新舊方向衝突時記清作者最新裁決，不悄悄抹除原始紀錄 |

執行前要形成 `ARCHIVE_MANIFEST.md`，每列至少有：精確原路徑、檔案性質、所屬篇章、是否為來源或鏡像、擬封存位置、保留於現行入口的設定、需更新的連結、待作者裁決事項、執行狀態。封存目的地須事先列出，不能搬完才補記。

作者未選定的範圍要明記「待定」；不把整個倉庫、全部文件或某個廣泛資料夾當成不經分類的搬移單位。

## 四、接下來依什麼次序做

### 1. 先留下完整需求與逐篇重估

先完成本輪入口規則、逐篇處理表與本安排，並把作者提到的仙感、人物成長、生活與修行混搭、主角重心、同伴獨立行動、伏筆發酵及 PM 統整責任接入新架構。

逐篇表需說清楚「這篇還值得留下什麼」「舊版病灶是什麼」「新版讀者期待是什麼」，不能只貼重構或保留標籤。具體項目見 [01_ARC_REASSESSMENT.md](01_ARC_REASSESSMENT.md)，本文件不另造一套衝突篇名或計數。

### 2. 把封存範圍列到可以實際操作

完成精確檔案表、來源與鏡像配對、混合設定分類及索引處理方式。作者已要求完整安排，因此盤點和提案可以繼續；涉及尚未選定的實際範圍，在表中集中提出裁決，不把未定範圍當成已定。

範圍與目的地清楚後，才依表做可追溯的封存與入口切換。保留復原對照，核對檔案未漏失、鏡像未脫節、設定與原作資料仍可讀；完成後再更新狀態。本輪尚未到這一步。

### 3. 先重建全書的大形狀

動手排篇以前，先對每個大故事留下簡短的「原始 idea／來源／最想看的經歷／新版如何兌現」紀錄。先確認值得看的故事，再配置前後篇功能；不先把舊章群換一套順序就稱為重新架構。Wonder、Desire、Fantasy Transformation 與讀者期待獨立檢查，不以因果或設定通過抵銷。

以各篇的主角目標、修行所得、重大失去、關係變化、敵友局勢與前後推動力重新排列。舊章群可合併、拆分、換位或淘汰；不要先把 931 章分配到新框架，也不要先訂各篇字數後再找情節塞滿。

這一步先確定全書讀者會依次經歷什麼：修行方式與世界尺度如何擴大，各篇有何獨特風味，劫的道與人格如何變化，劫瘋、劫與文奕及其他人物線怎樣相遇又分開。小故事要由人物欲望與事件後果引出；可有閒日，也可有隔數篇才發酵的餘波，不要求每場生活戲都承擔大主線任務。

### 4. 古界與帝關的病灶提早設計，其他篇同步接線

古界與帝關是優先看清新版方向的兩個重構支點：古界要兌現高階萬族修仙世界，帝關要兌現兩界大道戰爭。兩者可並行設計其核心衝突、修行吸引力與高潮規模，及早檢查前期鋪墊是否足夠。

這不等於先寫後期正文，也不等於把全書等到古界做完才開始思考。古世劫線與界路同時檢查各自的文明經歷、探索感與同伴主體性，避免四個大篇只是換地名的救援／工程故事。

### 5. 寫全書大綱，再寫每篇完整梗概

先有能看清首尾與轉折的全書大綱，再為各篇寫成可讀的故事梗概。梗概至少讓人理解：誰想做什麼、為何在此時出發、如何遭遇阻礙、如何嘗試並付出代價、轉折從何而來、高潮如何完成、離開時人與世界改變了什麼。

梗概必須有完整起承轉合，不能只列設定名詞、場景清單或「後續安排一場大戰」。但也不在方向未定時展開成逐章正文；人物對話與場景示例以能判斷味道為度。

所有篇的梗概要先擺在一起檢查。看到重複、斷裂、人物長期消失、修行所得不足或境界跳躍，就回改架構與梗概。不能以「這篇已寫了很多」阻止調整。

### 6. 作者看過全書方向後，再排正文

將全書架構、逐篇梗概、尚未解決的少數分歧一起交作者判斷，確認故事是否值得期待、篇與篇是否自然推進、主角及同伴是否真的成長。

方向確認後，再決定正文開寫位置、篇章長短與 agent 分工。寫書階段可多 agent 交叉創作與審查，由 PM 統合故事連貫；一般討論仍依作者偏好集中於專門窗口，不把每次發想都拆成多人互相覆蓋設定。

| 升龍③仙界 | 暫留白 | 不以現階段提案補成定案，不提前分配正式正文或用後期答案反鎖前期 |

## 七、作者要確認的幾個關鍵點

1. **設定取捨**：全書調整範圍已明確；哪些人物／能力設定隨新故事改動，須有具體方案與理由。封存清單由PM先核對，無需反覆詢問已授權的記錄與盤點工作。
2. **新全書架構**：大篇主題、先後、可合併／拆分之處與核心人物走向。舊章數不作默認答案。
3. **全書梗概方向**：各篇一起閱讀後，確認主角目標、修行吸引力、起承轉合、關係變化與篇際連貫。單篇有趣不代表全書已成立。
4. **正文起跑**：在整體方向確認後，才安排開寫範圍與創作分工；升龍③仙界留白項不藉此默認定案。

已確認的作者核心不必每步重問；未確認的新機制、境界正式邊界、隊伍大改或關鍵命運則在相應梗概中提出可判斷的具體方案。所有確認都須留下結果，不能以 agent 互相贊同代替作者決定。
